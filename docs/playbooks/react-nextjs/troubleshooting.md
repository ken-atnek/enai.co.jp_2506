# Troubleshooting

React / Next.js で詰まったときに、症状から確認するための逆引きメモです。

まず「どのAPIを使うか」ではなく、「何がユーザー体験を悪くしているか」を見る。

## 入力中に一覧表示が重い

### まず疑うこと

入力値の更新と、一覧の再計算・再描画が同じ優先度で走っている可能性。

### 確認すること

- 入力のたびに重い filter / sort / map が走っていないか
- 大量のDOMを毎回描画していないか
- URL検索パラメータ更新やルーティングが絡んでいないか
- 入力欄そのものが遅いのか、結果表示だけが遅いのか

### 対応方針

- 入力値は即時更新する
- 結果表示側に `useDeferredValue` を検討する
- 条件変更や重い state 更新には `useTransition` を検討する
- 必要ならメモ化、ページング、仮想リストも合わせて検討する

### 避けること

- 原因を見ずに debounce だけ入れる
- 入力欄自体の反応まで遅くする
- 重い計算や描画の構造を放置したまま、React APIだけで解決しようとする

- `patterns.md` の「入力と重い更新を分ける」
- `articles/2026-09-03-ics-react-ux.md`

## ローディング表示で画面がチラつく

### まず疑うこと

新しいデータを待つたびに、既存の表示を消して fallback に差し替えている可能性。

### 確認すること

- Suspense の境界が大きすぎないか
- 既存コンテンツを残した方が自然な画面ではないか
- ユーザー操作のたびに全体ローディングになっていないか

### 対応方針

- `<Suspense>` の境界を意味のある単位に分ける
- 既存表示を残したい更新は `startTransition` を検討する
- 検索結果などは `useDeferredValue` で古い結果を残す

### 避けること

- ページ全体を毎回ローディング表示に戻す
- 細かい領域ごとに無計画にスピナーを出す

### 関連

- `patterns.md` の「部分的に待たせるローディング」
- `patterns.md` の「入力と重い更新を分ける」

## いいね・お気に入りの反応が遅い

### まず疑うこと

API完了までUI更新を待っている可能性。

### 確認すること

- 操作の成功確率が高いか
- 失敗時に元の状態へ戻せるか
- ユーザーに即時反応を返す価値が高い操作か

### 対応方針

- `useOptimistic` で楽観的更新を検討する
- 保存完了後に確定状態を更新する
- 失敗時のエラー表示と復元を用意する

### 避けること

- 決済や予約確定など重要操作に安易に使う
- 失敗時の戻し方を決めずに先にUIだけ変える

### 関連

- `patterns.md` の「楽観的更新」
- `articles/2026-09-03-ics-react-ux.md`

## ステップフォームやタブの入力が消える

### まず疑うこと

表示切り替えのたびにコンポーネントがアンマウントされ、内部 state が破棄されている可能性。

### 確認すること

- `{condition && <Component />}` のようにマウントごと切り替えていないか
- 入力値を親 state やフォーム管理側で保持すべきか
- 隠したUIが再表示される可能性は高いか

### 対応方針

- 対応環境なら `<Activity>` で状態保持を検討する
- 安定性を優先する案件では、親 state やフォームライブラリで保持する
- 頻繁に戻るステップでは、アンマウントしない設計を検討する

### 避けること

- 対応状況が曖昧なまま `<Activity>` 前提にする
- ほとんど使われない画面まで保持して無駄な処理を増やす

### 関連

- `patterns.md` の「非表示UIの状態保持」
- `articles/2026-09-03-ics-react-ux.md`
