# useStateとuseEffectだけじゃもったいない！ ユーザー体験を改善するReactの便利機能

## URL

https://ics.media/entry/260903/

## この記事の要点

React 18 / 19 以降で使える、ユーザー体験改善に効くAPIの整理。

- `<Suspense>` で準備できた部分から表示する
- `useTransition` で重い state 更新の優先度を下げる
- `useDeferredValue` で古い表示を残しながら新しい描画を待つ
- `useOptimistic` でAPI完了前にUIへ反映する
- `<Activity>` で非表示UIの state を保持し、表示前の準備にも使う

## 実案件で使うなら

検索、絞り込み、お気に入り、フォーム、タブ、ステップUIで特に使いどころがある。

### 検索 / 絞り込み

入力欄は即時反応させ、結果表示だけ遅らせる。古い結果を残す方が自然なら `useDeferredValue` を検討する。

### 料金計算 / 重い条件変更

ユーザー操作の反応を優先し、計算結果や表示更新は `useTransition` で優先度を下げる。

### いいね / お気に入り

成功確率が高く、失敗時に戻せる操作なら `useOptimistic` を検討する。

### タブ / ステップフォーム

入力中の内容を消したくない場合は、アンマウントしない設計を優先する。対応環境なら `<Activity>` も候補にする。

## 判断基準

- 画面全体を待たせているなら、Suspense の境界を分ける
- 入力まで重いなら、入力 state と表示 state を分ける
- 新しい結果待ちでチラつくなら、古い表示を残す
- API完了待ちで反応が遅いなら、楽観的更新を検討する
- 非表示にしただけで入力が消えるなら、アンマウントしていないか確認する

## 避けること

- 何でも debounce で解決しようとする
- ページ全体をすぐローディングに戻す
- 失敗時の設計なしで楽観的更新を入れる
- React / Next.js の対応バージョンを確認せずに `<Activity>` 前提で組む
- 本当の原因がデータ量や不要な再レンダリングなのに、API選定だけで隠す
