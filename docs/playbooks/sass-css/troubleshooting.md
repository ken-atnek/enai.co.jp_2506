# Troubleshooting

Sass / CSS で詰まったときに、症状から確認するための逆引きメモです。

まず「どの指定を足すか」ではなく、「どの制約が崩れを起こしているか」を見る。

## 追加テンプレート

```md
## 症状

### まず疑うこと

### 確認すること

### 対応方針

### 避けること

### 関連
```

## 横スクロールが出る

### まず疑うこと

固定幅、長い文字列、画像、Grid / Flex の最小幅が親幅を超えている可能性。

### 確認すること

- `width: 100vw` を通常コンテンツに使っていないか
- `min-width` や固定幅がSP幅を超えていないか
- Flex / Grid の子要素に `min-width: auto` の影響がないか
- 画像、iframe、table、pre が親幅を超えていないか

### 対応方針

- 固定幅を `max-width` と `width: 100%` に置き換える
- Flex / Grid の子要素に必要なら `min-width: 0` を指定する
- 画像や埋め込み要素は親幅内に収める
- 横スクロールが必要な要素だけに `overflow-x: auto` を付ける

### 避けること

- 原因を特定せずページ全体へ `overflow-x: hidden` を入れる
- 1要素の問題を全体レイアウトの上書きで隠す

### 関連

- `responsive.md` の「幅は固定値より制約で管理する」

## テキストやボタンが重なる

### まず疑うこと

固定高さ、絶対配置、狭い固定幅、改行条件の不足が原因になっている可能性。

### 確認すること

- テキスト量が増えたときに高さが伸びるか
- `height` 固定で中身を閉じ込めていないか
- 絶対配置の要素が通常フローの要素と重なっていないか
- ボタン内の文字が折り返しまたは縮小できるか

### 対応方針

- 固定高さを避け、必要なら `min-height` にする
- テキスト量が変わる要素は通常フローで配置する
- コンパクトなUIでは文字数、余白、アイコンサイズをセットで調整する
- 長い単語には `overflow-wrap` を検討する

### 避けること

- 見た目合わせのために高さだけを増やす
- 可変テキストを絶対配置で重ねる
- ボタン幅だけを固定してテキスト量を無視する

### 関連

- `layout.md` の「絶対配置は役割を限定する」

## 余白が画面ごとに揃わない

### まず疑うこと

セクション、コンテナ、コンポーネントの責務が混ざり、複数階層で余白を持っている可能性。

### 確認すること

- 上下余白を親と子のどちらが持つべきか
- 左右余白がコンテナと部品で二重になっていないか
- `margin` の相殺や隣接要素の影響を受けていないか
- 同じ見た目の部品に別々の余白指定が入っていないか

### 対応方針

- セクション余白、コンテナ幅、部品内余白を分ける
- 一覧や横並びの間隔は `gap` を優先する
- 共通化できる余白は案件側の既存トークンや変数に寄せる

### 避けること

- 個別要素の `margin-top` / `margin-bottom` でページ全体を調整する
- 似た余白値を場当たり的に増やす
- コンポーネントにページ固有の外側余白を持たせる

### 関連

- `layout.md` の「レイアウトの責務を分ける」

## PCでは良いがSPで窮屈になる

### まず疑うこと

PC前提の列数、余白、固定幅、文字サイズ、画像比率がSP幅に合っていない可能性。

### 確認すること

- カードやメディアが縦積みに切り替わる幅は適切か
- 左右余白がSP画面に対して広すぎないか
- ボタンやフォームがタップしやすいサイズか
- 画像が必要以上に小さく、または大きく表示されていないか

### 対応方針

- まず可変幅で自然に縮める
- 読みにくくなる幅でブレイクポイントを追加する
- SPでは情報順序と密度を見直す
- コンポーネント単位の例外は局所的に閉じる

### 避けること

- すべてをPC比率のまま縮小する
- 画面幅ごとの上書きを増やして原因を追いにくくする
- デバイス名だけでブレイクポイントを決める

### 関連

- `responsive.md` の「ブレイクポイントは見た目の破綻で決める」
- `responsive.md` の「SPでは順序と密度を見直す」
