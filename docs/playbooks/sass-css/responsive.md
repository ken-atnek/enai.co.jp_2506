# Responsive

Sass / CSS のレスポンシブ実装で迷ったときに確認する判断基準です。

まず固定幅の調整ではなく、コンテンツがどの幅で読みにくくなるか、どの要素が先に崩れるかを見ます。

## 追加テンプレート

```md
## テーマ

### 使う場面

### 実装方針

### 判断基準

### 避けること

### 関連
```

## ブレイクポイントは見た目の破綻で決める

### 使う場面

PC / tablet / SP の差分を作る場面。

### 実装方針

- まず可変幅で自然に縮む構造を作る
- ブレイクポイントはデバイス名ではなく、表示が破綻する幅で判断する
- 案件側に既存のブレイクポイントや mixin がある場合はそれを優先する
- 例外的な調整はコンポーネント単位に閉じる

### 判断基準

- テキストの1行が長すぎる、短すぎる
- 画像やカードが窮屈になる
- ナビゲーションやボタンが折り返して読みにくい
- 余白が画面幅に対して過剰または不足している

### 避けること

- 端末名だけで `768px` / `1024px` を機械的に増やす
- 1つの違和感に対して全体のブレイクポイントを追加する
- PC用の固定値をSPで上書きし続ける

## 幅は固定値より制約で管理する

### 使う場面

コンテナ、カード、画像、フォーム、ボタンなどの横幅を決める場面。

### 実装方針

- `width: 100%` と `max-width` の組み合わせを基本にする
- 読ませる本文は行長を意識する
- 画像や動画は `aspect-ratio` で比率を安定させる
- 最小幅が必要なUIは `min-width` と折り返し条件をセットで見る

### 判断基準

- 親幅に追従してよい要素か
- 最大幅を超えたときに広がる意味があるか
- 最小幅を下回ったときに縮めるか、折り返すか、縦積みにするか

### 避けること

- `width: 〇〇px` だけで画面幅に対応する
- テキスト入りボタンやカードに狭すぎる固定幅を与える
- 画像比率を高さ固定だけで合わせる

## SPでは順序と密度を見直す

### 使う場面

PCで横並び、SPで縦積みにする画面。

### 実装方針

- SPで重要な情報が先に見える順序にする
- PCの余白をそのまま縮小せず、密度を調整する
- ボタンやフォームはタップしやすい高さと余白を確保する
- 横スクロールが必要な表や比較UIは、スクロール範囲を明確にする

### 判断基準

- 縦積みにしたときに情報の順番が自然か
- 余白が広すぎて情報到達が遅くなっていないか
- タップ対象が小さすぎないか
- 横スクロールがページ全体に発生していないか

### 避けること

- PCの見た目をそのまま縮める
- `order` で視覚順だけ変えて、読み上げ順やフォーカス順を無視する
- 1箇所のはみ出しを隠すために全体へ `overflow-x: hidden` を入れる
